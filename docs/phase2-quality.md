# Phase 2 — 번역 품질과 대화 문맥

## 요구사항과 적용 범위

초기 개발 지시서의 Phase 2를 현재 1:1·그룹 및 4개 선택 언어 구성에 적용한다. 기존 기능과 설정 파일을 유지한다. 관리자 웹 UI, 음성·Telegram 확장은 별도 단계다. 최초 명세의 관리자 전용 명령은 이후 사용자가 선택한 누구나 설정 정책을 따른다. 1:1에서는 본인 대화, 그룹에서는 참여자 누구나 해당 그룹 설정을 바꾼다. LINE 그룹 관리자 권한을 추정하거나 검사하지 않는다.

| 항목 | 구현 |
| --- | --- |
| 역번역 | 번역 후보를 별도 요청으로 원문 언어로 다시 번역 |
| 의미 검증 | 원문·후보·역번역을 비교해 PASS / WARNING / FAIL 반환 |
| 검증 항목 | 숫자, 날짜·시간, 금액, 이름·장소, 긍정·부정, 질문·명령, 누락, 추가 정보 |
| 숫자 검사 | 모델 판정과 별도로 원문·역번역 숫자를 비교. 아라비아·태국 등 유니코드 숫자와 천 단위 구분 정규화 |
| 재번역 | FAIL일 때 시간 예산 안에서 최대 한 번. 원문과 검사 코드로 다시 번역 후 재검증 |
| 위험한 의미 왜곡 | 수정본에서 PASS로 해소되지 않으면 후보를 숨기고 확인 안내만 회신 |
| 검증 모델 분리 | 번역 서버·모델과 별도로 서버·모델·키 설정 가능 |
| 문맥 | 대화별 원문 최대 10개, 기본 600초 만료, 중복 방지, OFF 지원 |
| 저장소 추상화 | ConversationContextStore 인터페이스, 기본 RAM 구현. Redis 불필요 |
| 채팅 명령 | 번역 ON/OFF, 검증 표시, 문맥 0/5/10, 상태·도움말 |

## 처리 흐름과 실패 정책

번역 → 역번역 → 의미 평가가 기본 3회 AI 호출이다. FAIL이면 번역·역번역·평가를 한 번 더 시도하므로 최대 6회다. 같은 모델을 사용하더라도 요청은 분리한다. 출력 JSON의 상태·문제 코드는 허용 목록으로 검사하며 모델이 임의로 만든 안내 문구나 추론 내용을 LINE에 그대로 붙이지 않는다.

- PASS: 모델과 숫자 검사에서 문제를 발견하지 못했다는 뜻이다. 정확성을 보증하지 않는다.
- WARNING: 불확실하거나 숫자가 문자로 바뀌어 추가 확인이 필요한 경우다. 이 상태만으로 자동 재번역하지 않는다.
- FAIL: 의미·숫자 등 실패가 확인되어 한 번 재번역한다. 위험 플래그가 없는 지속 FAIL은 경고와 번역 후보를 함께 보낸다.
- 위험 플래그가 있으면 표시 설정과 관계없이 후보를 숨긴다. 재번역 검증 실패·WARNING으로는 이전 위험 판정을 지우지 않는다.
- 검증 API 오류·잘못된 JSON·시간 초과는 PASS로 바꾸지 않는다. WARNING 및 미검증 안내를 표시한다. 이미 위험 판정된 후보는 이 경우에도 숨긴다.
- 원문·후보·역번역이 길어 LINE 회신 한도를 넘으면 내용을 임의로 자르지 않고 분할 입력 안내를 보낸다. 역번역 표시만 최대 800자로 제한한다.

숫자 차이는 단순 문자열 유사도와 다르지만 표기 차이 때문에 오탐할 수 있다. 숫자가 양쪽에 있으면서 다르면 위험한 FAIL로 처리하고, 한쪽이 숫자를 글자로 쓴 경우에는 WARNING으로 둔다. 이름·장소와 문장 의도는 AI 의미 평가에 의존하므로 사람 검수도 필요하다. 같은 모델의 번역·검증에는 공통 오류가 남을 수 있다.

## 채팅 명령

| 명령 | 동작 |
| --- | --- |
| `/번역 켜기`, `/번역 끄기` | 해당 대화 번역 ON/OFF. 끄면 저장 문맥도 삭제 |
| `/검증 전체` | 번역문과 검증 상태·역번역 표시 |
| `/검증 경고` | PASS는 번역문만, WARNING/FAIL은 검증 정보 표시 |
| `/검증 숨김` | 정상 검증 정보 숨김. 검증 실행은 계속하고 위험 차단·지속 FAIL·검증 불가 안내는 유지 |
| `/문맥 0` | 문맥 저장·사용 OFF, 기존 문맥 즉시 삭제 |
| `/문맥 5`, `/문맥 10` | 최근 메시지 수 변경, 기존 문맥 비우고 새로 축적 |
| `/상태`, `/설정` | 언어 쌍·기본언어·번역 ON/OFF·검증 실행/표시·문맥 설정 |
| `/도움말` | 전체 명령 안내 |

이 명령은 번역이 꺼진 대화에서도 동작한다. 기존 `/언어`, `/기본언어` 명령은 유지한다. 오래된 설정 명령과 동일 이벤트 재전송은 이전처럼 차단한다. 설정은 `chat_groups`와 신규 `chat_quality_settings`에 저장하며 기존 테이블 데이터를 삭제하거나 열 구조를 바꾸지 않는다. 새 테이블은 시작 시 자동 생성한다.

LINE 표시에서는 역번역문 앞에 상태 `✅ / ⚠️ / ❌`를 바로 붙인다. 예: `✅ 내일 만나요.` 별도 역번역 아이콘과 `검증: PASS/WARNING/FAIL`, `역번역:` 접두어는 사용하지 않는다. 경고 사유는 다음 줄에 `(의미누락, 정보추가)`처럼 괄호로 묶어 표시하고 차단 안내는 유지하며 API 결과의 상태 코드는 그대로다.

## 설정 파일

프로젝트 루트의 `config/application.properties`를 사용한다. 기존 키·토큰은 유지하며 아래 값은 생략해도 기본값으로 적용된다.

```properties
app.verification.enabled=true
app.verification.budget-ms=30000
app.context.max-messages=10
app.context.ttl-seconds=600
```

전역 검증 실행 자체를 끄려면 `app.verification.enabled=false`로 바꾸고 재시작한다. `/검증 숨김`은 실행 OFF와 다르다. 예산은 전체 번역·검증에 기본 30초, 설정 가능 범위 1~35초다. 각 API 요청은 기존 AI timeout과 남은 전체 예산 중 짧은 값으로 제한한다. 오래 대기한 작업은 LINE Reply 여유 시간에 맞춰 더 줄이고 재번역을 생략할 수 있다. 시간 예산이 부족하면 위험 판정을 무시하거나 검증 성공으로 위장하지 않는다.

검증 서버를 분리하려면 같은 파일에 다음을 추가한다. 아래 주소·모델은 예시이며 실제 별도 모델을 띄워야 한다.

```properties
app.verification.provider=local-qwen
app.verification.base-url=http://127.0.0.1:8083/v1
app.verification.model=verification-model
app.verification.key=
```

다른 HTTPS OpenAI 호환 서버는 `provider=external`과 해당 서버 키를 설정한다. 서버 주소가 다르면 번역용 키를 자동 재사용하지 않는다. 별도 설정이 없으면 현재 Qwen과 같은 서버·모델을 쓰며 독립 모델 검증은 아니다. Compose에서는 `VERIFICATION_ENABLED`, `VERIFICATION_BUDGET_MS`, `CONTEXT_MAX_MESSAGES`, `CONTEXT_TTL_SECONDS`로 기본 동작을 설정할 수 있다.

## 문맥과 개인정보

LINE 회신에 성공한 원문만 RAM에 저장한다. 명령어·번역문·역번역문·봇 메시지는 저장하지 않는다. 위험 차단·지속 FAIL 메시지는 문맥에 넣지 않는다. 이벤트 ID로 중복 저장을 방지하고 대화 ID별로 분리한다. 서버 재시작 시 문맥 원문은 사라지며 문맥 개수·검증 표시 설정은 DB에 남는다.

기본 문맥은 최근 10개, 600초이며 실제 모델에 보내는 문맥은 총 4,000자 이하로 제한한다. 4,000자 초과 원문은 문맥에 남기지 않는다. 최대 1,000개 대화를 보관하고 초과하면 오래 사용하지 않은 대화를 비운다. 만료된 항목은 접근 시와 30초 주기 정리에서 제거한다. `/문맥 0`, `/번역 끄기`, 번역 언어 쌍 변경 시 해당 대화의 문맥을 비운다. 문맥은 요청의 별도 인용 데이터로 전달하고 명령으로 따르지 않도록 지시한다. 모델의 프롬프트 주입 방어를 완전히 보증하는 것은 아니다.

## 검증 방법

일반 자동 테스트는 외부 LINE·AI를 호출하지 않는다. Mock 검증 PASS는 동작 시험용으로 모사한 결과이며 번역 품질의 근거가 아니다.

```powershell
mvn -f backend/pom.xml test
```

실제 로컬 Qwen을 사용하는 소규모 평가:

```powershell
mvn -f backend/pom.xml "-Dtest=QwenQualityEvaluationTest" "-Dquality.eval=true" test
```

기본 `http://127.0.0.1:8082/v1`, `Qwen3-14B`를 사용한다. 필요하면 `-Dquality.base-url=...`, `-Dquality.model=...`을 추가한다. 이 평가는 LINE에 메시지를 보내지 않는다. 네 언어의 양방향 예문 8개와 의도적으로 시간을 바꾼 후보 1개를 평가하고 `backend/target/quality-evaluation.json`에 결과·판정·시도를 저장한다. 데이터는 합성 예문이며 사용자의 실제 대화가 아니다. 평가는 기본 테스트에서 제외하고 명시적으로 실행한다.

이 작은 평가로 실제 번역 정확도 전체를 결론 내리지 않는다. 다음 품질 작업은 모국어 검수된 회귀 문장 확대, 오탐·미탐 분류, 이름·금액·날짜·부정·구어체 사례 보강, 독립 모델 비교다. 검증을 켜면 기존 1회 번역 대비 지연과 처리량이 바뀌므로 이전 사용자 수 추정은 그대로 적용하지 않는다.

## 1:1 대화의 생략된 주어

질문은 보통 상대방, 의도·자기 상태는 보통 화자로 해석하되 명시된 이름·호칭과 실제 문맥을 우선한다. 불확실하면 주어 생략을 유지하고 성별·사실을 만들지 않는다. “밥 먹었어?”는 상대방, “지금 출발할게”는 화자, “보고 싶어”는 화자에서 상대방, “민수는 도착했어?”는 제3자다.

검증은 원문과 후보의 참여자를 직접 비교하고 역할 뒤바뀜을 PARTICIPANT(화자·상대방)로 표시한다. 원문 언어가 명시되면 역번역 요청에는 후보만 전달하여 원문에 맞춰 고치는 현상을 줄인다.

Phase 2 필수 기능인 역번역·의미 검증·1회 재번역·문맥·설정 명령은 구현했다. 다국어 사람 검수 정답집 확대와 별도 모델 비교는 지속적인 품질 개선 과제다. 자동 PASS는 정확도 보장이 아니다.

실제 주어 평가는 `mvn -f backend/pom.xml -Dtest=TwoPersonConversationEvaluationTest -Dquality.pronouns=true test`로 별도 실행한다.
